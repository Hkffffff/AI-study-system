# 05 前端页面规划

技术栈：Vue 3 + TypeScript + Vite + Element Plus + Vue Router + Pinia。附加依赖：`axios`、`markdown-it`（`html: false`）、`katex`。

## 1. 信息架构与导航

```
┌──────────────────────────────────────────────────────────────────────┐
│ [● 数学一 ▾]  空间切换器（空间颜色 + 名称，始终可见）        ⚙ 设置     │
├────────────┬─────────────────────────────────────────────────────────┤
│ 🏠 首页     │                                                         │
│ 📁 资料库   │                 主内容区                                │
│ 📝 错题     │                                                         │
│ 🤖 AI 助手  │  ← MVP 中禁用，标注「规划中」（README C7）               │
│ 📊 学习画像 │  ← MVP 中禁用，标注「规划中」（README C7）               │
└────────────┴─────────────────────────────────────────────────────────┘
```

- 当前空间写在 URL 里（`/s/:spaceId/...`），这样刷新、收藏和多标签页时空间都不会串。空间颜色同时用于顶栏标识条和侧栏高亮。
- 空间切换器下拉内容：空间列表、「新建空间」、「管理空间」。
- 最近一次使用的空间保存在 `localStorage`，访问 `/` 时自动跳转过去。

## 3. 页面说明

### 3.1 空间首页 `/home`

- **快速录入**（主按钮）：拖入、粘贴或选择图片/PDF → 选择归档（默认上次用的）→ 进入建题向导。这是最常用的入口，追求最少的点击。
- **待处理**：分析中、分析失败、**待确认**（`UNREVIEWED`）的题目。
- 最近上传的文件、最近的错题。
- （预留位）今日待复习：MVP 不显示【R5】。

### 3.2 资料库 `/archives` 与归档详情

- 左侧是归档列表（可以按 Subject 分组显示），右侧是文件网格（缩略图、文件名、页数、上传时间、「已被 N 道题引用」标记）。
- 上传区：拖拽、多选、Ctrl+V；每个文件单独显示进度和失败原因。
- 文件操作：查看、移动到其他归档、从此文件建题、删除（被引用时禁用）。

### 3.3 文件查看器 `/files/:fileId`

- 图片：缩放、平移、**仅视图层**旋转（不修改原件）。
- PDF：左侧是页缩略图条（按需加载），右侧是当前页的大图；提供「在新标签页打开原始 PDF」（浏览器原生查看器）。
- 多选页面 → 「用选中页建题」。

### 3.4 建题向导 `/questions/new`

单页分三个区域，不做多步跳转：

1. **来源**：已选的图片/页面缩略图列表，可以拖动排序；每个来源有一个角色下拉框（题目 / 我的解答 / 标准答案 / 混合，默认混合）；可以继续从资料库挑选或直接上传。最多 6 个来源（超出时提示）。
2. **信息**：Subject（可选，默认使用归档的 Subject）、题号/位置提示、我的答案（文字，可选）、标准答案（可选）、补充说明（可选）。
3. **分析**：「创建后立即分析」开关（默认开），模型下拉框（只列出满足 `QUESTION_ANALYSIS` 能力要求的模型，默认使用系统默认模型，并记住上次的选择）。

提交后跳转到题目详情页，分析状态实时更新。

### 3.5 错题列表 `/questions`

- 筛选：Subject、归档、知识点、错误类型、状态（未分析 / 待确认 / 已确认 / 分析失败）、关键词。
- 列表项：缩略图、标题或题干摘要、Subject、知识点标签、错误类型、**确认状态标记**（AI 草稿 / 已确认）、可信度等级（低可信度时显示黄色标记）、创建时间。
- 表格和卡片两种视图可以切换（MVP 可以只做表格）。

### 3.6 题目详情 `/questions/:id`（核心页面）

```
┌──────────────────────────────┬────────────────────────────────────────┐
│ 原始资料                     │ [题目] [AI 分析 v3 ▾] [对话]           │
│ ┌──────────────────────────┐ │                                        │
│ │ 来源 1 · 题目  (Tab)     │ │ ⚠ 低可信度：以下 2 处无法辨认…         │
│ │ 来源 2 · 我的解答        │ │ 状态：AI 草稿（v3，claude-main，        │
│ │ ……                       │ │       prompt math/question-analysis v1）│
│ │   [图片 / PDF 页查看器]  │ │                                        │
│ └──────────────────────────┘ │ ▸ 识别结果（题目 / 我的解答 / 标准答案）│
│                              │ ▸ 核心知识点                           │
│                              │ ▸ 错因分析                             │
│                              │ ▸ 正确思路                             │
│                              │ ▸ 相关知识 / 易混淆                    │
│                              │ ▸ 元数据：错误类型 · 难度 · 可信度      │
│                              │                                        │
│                              │ [确认] [修正] [驳回] [重新分析 ▾]       │
└──────────────────────────────┴────────────────────────────────────────┘
```

- **左栏始终显示原件**，方便和识别结果对照（Archive 是事实来源）。
- **「题目」Tab**：已确认的题干、我的解答、标准答案、补充说明、Subject、知识点（可以增删）；可编辑。
- **「AI 分析」Tab**：
  - 版本下拉框：`v3 · AI 草稿 · claude-main · 09-26 14:02`、`v2 · 已确认 ✓`、`v1 · 已修正`……；可以查看任一历史版本。
  - 顶部信息条显示 Provider、模型、Prompt 版本和 token 用量（可折叠）【R2】。
  - **可信度展示**【R3】：等级徽标（高/中/低）+ 模型自报数值 + 「不确定之处」列表；「无法辨认的部分」逐条列出，并标明位置（例如「来源 2 第 3 行」），点击后左栏切换到对应来源。
  - 所有文本用 Markdown + KaTeX 渲染。
  - 执行中显示骨架屏和已用时间；失败时显示原因和「重试」按钮。
- **确认对话框**（点击「确认」）：
  1. 「采用识别结果到题目」复选框，展开后可以编辑题干、我的解答、标准答案，并与当前已确认的内容对比；
  2. 知识点勾选：已存在的默认勾选，AI 新提议的默认不勾选（标注「新」）；
  3. 如果存在无法辨认的部分，要勾选「我已核对不确定之处」才能提交。
- **修正**：进入编辑模式（各段落变成文本框，知识点可以增删，错误类型用下拉框）→ 保存后生成新版本（已确认）。
- **驳回**：填写原因（可选）→ 可以接着「补充信息后重新分析」。
- **重新分析**下拉：选择模型、选择原因（换模型 / 补充了信息 / 其他）、附加说明、「以我确认的识别文本为准」开关。
- **「对话」Tab**：见 3.7。

### 3.7 题目对话（详情页 Tab）

- 会话列表（可以新建或切换）+ 消息区 + 输入框。
- 输入框旁边：模型下拉框（只列出支持流式输出的模型）、「附带原图」开关（默认关闭，只发送识别文本和分析内容，以节省 token）。
- 助手消息下方显示小字的模型名；支持「停止生成」。
- 流式渲染：边接收边渲染 Markdown，公式在消息完成后再渲染一次，避免显示残缺的 LaTeX。

### 3.8 设置

- `/s/:spaceId/settings`：名称、颜色、描述、AI 分析配置（下拉框）、空间附加 AI 指令；**Subject 管理**（列表、新增、重命名、排序、附加指令、停用或删除）。
- `/settings`：模型列表（来自 `/api/ai/models`）：名称、Provider、能力标签（图片输入 / 结构化输出 / 流式输出……）、是否可用（有无 Key）；各任务的默认模型（MVP 只读，来自后端配置）。

## 4. 前端工程结构

```
frontend/src/
├─ api/                 # http.ts（axios 实例、ProblemDetail 错误处理）+ 各领域 API
│  ├─ spaces.ts  subjects.ts  archives.ts  files.ts
│  ├─ questions.ts  knowledgePoints.ts  analyses.ts  ai.ts  chat.ts
├─ types/               # 与后端 DTO 对应的 TS 类型
├─ stores/
│  ├─ space.ts          # 当前空间、空间列表、Subject 列表（随空间切换刷新）
│  └─ aiModels.ts       # 模型列表及能力、各任务默认模型、上次选择
├─ router/index.ts      # 路由守卫：校验 spaceId 存在，并同步到 store
├─ layouts/AppLayout.vue
├─ views/
│  ├─ spaces/  home/  archives/  files/  questions/  knowledge/  settings/
│  └─ placeholder/ComingSoon.vue
├─ components/
│  ├─ common/   MarkdownView.vue  SpaceSwitcher.vue  ModelSelect.vue  ConfidenceBadge.vue
│  ├─ file/     FileUploader.vue  FileGrid.vue  ImageViewer.vue  PdfPageStrip.vue
│  ├─ question/ SourceEditor.vue  QuestionFilters.vue  KnowledgePointTags.vue
│  ├─ analysis/ AnalysisPanel.vue  VersionSelect.vue  ConfirmDialog.vue
│  │            CorrectionEditor.vue  UncertaintyList.vue  ReanalyzeMenu.vue
│  └─ chat/     ChatPanel.vue  ChatMessageItem.vue
└─ utils/       sse.ts（基于 fetch 的 SSE 解析） poll.ts  format.ts
```

**状态管理原则**：Pinia 只存跨页面共享的状态（当前空间、模型列表）；页面数据（题目、分析）由页面组件自己加载，不做全局缓存，避免数据不一致。

**安全**：`markdown-it` 关闭 HTML；AI 输出不经过 `v-html` 直接插入，只输出 Markdown 渲染结果；图片 URL 只来自本系统的 API。
