# 01 产品需求分析

## 1. 产品定位

一个**个人使用**的 AI 学习管理系统。首个场景是考研备考（数学一、408），但架构上要支持任意数量的学习空间（Java、数据库、英语……）。

它不是 AI 聊天机器人，也不是传统错题本，而是把下面三件事串起来：

```
原始资料（Archive）→ 结构化错题（Question）→ AI 分析与对话（AI）
                                   ↓
                   长期学习画像（Learning Profile，MVP 之后）
```

## 2. 用户与使用场景

| 项目 | 说明 |
|---|---|
| 用户 | 只有 1 人（本人），无需登录，本机使用 |
| 设备 | 桌面浏览器为主；照片由手机拍摄后传到电脑再上传（MVP 不支持手机直传，README C9）；手机照片请使用 JPG（不支持 HEIC，README C8） |
| 典型输入 | 手机拍的题目和手写解答、试卷或习题册的扫描 PDF、电子版真题 PDF |
| 使用频率 | 每天多次录入错题，偶尔集中复盘 |

### 典型场景

1. **做完一套题后录入错题**：上传 3 张照片（题目、我的草稿、标准答案），建一道错题，AI 识别题目和我的过程，指出错在哪里，我确认后保存。
2. **整本 PDF 归档**：上传一份 30 页的真题 PDF 到「2023 真题」归档，之后从第 5 页、第 6 页各建一道错题。
3. **针对某题追问**：在题目详情页问 AI「为什么这里不能用洛必达？」，对话上下文限定在这道题。
4. **纠正 AI**：AI 把手写的 ∫ 识别错了，或者把老师的批注当成了我的解答。我修改识别结果后重新分析，旧版本保留。
5. **复盘**：按 Subject、知识点、错误类型筛选错题，查看原图和已确认的分析。

## 3. 核心业务流程

```
上传资料 ──► 选择页面/图片，标注角色 ──► 创建题目 ──► AI 识别 + 分析（异步）
                                                              │
               ┌──────────────────────────────────────────────┘
               ▼
       AI 结果（待确认）──► 用户审阅 ──┬─ 确认 ────────► 已确认结果（可信数据）
                                       ├─ 修正后确认 ──► 新版本（用户修正）
                                       └─ 驳回 ────────► 补充信息 / 换模型重新分析
                                                              │
                                                              ▼
                                            针对题目的 AI 对话 ──► 日后复盘
```

## 4. 功能需求

### 4.1 LearningSpace（学习空间）

| 编号 | 需求 | MVP |
|---|---|---|
| S-1 | 创建、编辑、归档学习空间（名称、描述、颜色、AI 分析配置 `ai_profile`、附加 AI 指令） | ✅ |
| S-2 | 切换当前空间，界面上始终清楚显示当前空间 | ✅ |
| S-3 | 空间之间的数据逻辑隔离：归档、文件、题目、知识点、对话都按空间隔离 | ✅ |
| S-4 | 不对「数学」「408」做硬编码；它们只是两条使用不同 `ai_profile` 的空间数据 | ✅ |

### 4.2 Subject（学科，轻量层）【评审 R1】

Subject 是空间下**可选**的分类层，例如：

- 数学一 → 高等数学、线性代数、概率论与数理统计
- 408 → 数据结构、计算机组成原理、操作系统、计算机网络

| 编号 | 需求 | MVP |
|---|---|---|
| SB-1 | 在空间内增删改 Subject（名称、排序、可选的附加 AI 指令） | ✅ |
| SB-2 | Archive、Question 和 KnowledgePoint 都可以选择一个 Subject，也可以不选 | ✅ |
| SB-3 | 题目列表可以按 Subject 筛选 | ✅ |
| SB-4 | AI 分析时，把题目所属 Subject 的名称和附加指令加入 Prompt | ✅ |

**不破坏 LearningSpace 设计的约束：**

- 所有核心数据的归属主键仍然是 `space_id`。Subject 只是可选的分组维度，不是新的隔离边界。
- Subject 不能跨空间。后端校验被引用的 Subject 与数据属于同一空间。
- 不设 Subject 的空间（例如「英语」）功能完全不受影响。
- Subject 不分层级（没有子学科）。更细的划分交给知识点。

### 4.3 Archive（归档）

| 编号 | 需求 | MVP |
|---|---|---|
| A-1 | 在空间内创建、编辑归档（名称、描述、可选 Subject） | ✅ |
| A-2 | 浏览归档内的文件（缩略图网格）；可以查看原件 | ✅ |
| A-3 | 文件可以不属于任何归档（「未归档」） | ✅ |
| A-4 | 文件可以移动到其他归档（只限同一空间内） | ✅ |
| A-5 | 只能删除空归档 | ✅ |

### 4.4 File（文件）

| 编号 | 需求 | MVP |
|---|---|---|
| F-1 | 上传图片（JPEG/PNG/WebP）和 PDF；支持拖拽、多选、**Ctrl+V 粘贴截图** | ✅ |
| F-2 | 服务端校验真实文件类型（魔数）和大小，不信任客户端提供的 MIME | ✅ |
| F-3 | 随时可以查看原件；PDF 可以按页浏览 | ✅ |
| F-4 | 原件不可修改；删除为软删除，被题目引用的文件不能删除 | ✅ |
| F-5 | PDF 的具体支持范围见 [07 §4](07-file-management.md#4-pdf-mvp-支持范围评审-r4) | ✅ |

### 4.5 Question（题目）

| 编号 | 需求 | MVP |
|---|---|---|
| Q-1 | 从一个或多个图片/PDF 页面建题；给每个来源标注角色：题目 / 我的解答 / 标准答案 / 混合 | ✅ |
| Q-2 | 可以填写题号或位置提示（如「第 3 题」）、我的答案文字、标准答案文字、补充说明 | ✅ |
| Q-3 | 建题后可以选择立即发起 AI 分析 | ✅ |
| Q-4 | 题目列表：按 Subject、归档、知识点、错误类型、确认状态和关键词筛选 | ✅ |
| Q-5 | 题目详情：原图、识别文本、分析版本、知识点、对话 | ✅ |
| Q-6 | 题干等字段来自用户确认后的识别结果，也可以手动编辑 | ✅ |
| Q-7 | 一页多题时由 AI 自动拆分 | ❌ 已确认暂时不做；用「位置提示」代替 |
| Q-8 | 在原图上框选题目区域 | ❌（后续；数据库已预留 `region` 字段） |
| Q-9 | 复习状态、掌握程度、下次复习时间 | ❌（**只预留数据库字段**，见 03 §3.5） |

### 4.6 AI 分析

**输入**（按题目组装，不跨题）：

- 来源图片或 PDF 页（带角色标签）
- 用户输入的答案文字、标准答案、补充说明
- 空间的 `ai_profile`、空间附加指令、Subject 附加指令
- 空间内已有知识点名称的列表（用于复用，数量有上限）

**输出**分两部分：

1. **识别结果（recognition）**：题目文本、我的解答过程、标准答案、批注/老师批改，以及看不清的部分。
2. **分析结果（analysis）**，四个核心输出：
   1. 核心知识点
   2. 错因分析
   3. 正确解题思路
   4. 相关知识和易混淆概念

   可选元数据：错误类型、难度、可信度、复习建议。

| 编号 | 需求 | MVP |
|---|---|---|
| AI-1 | 异步分析，界面显示进度状态，失败时可以重试 | ✅ |
| AI-2 | 分析前可以选择模型（只列出具备所需能力的模型） | ✅ |
| AI-3 | 结构化输出，入库前先做校验 | ✅ |
| AI-4 | 版本化：每次分析或修正都是新版本，记录 Provider、模型、Prompt 版本 | ✅ |
| AI-5 | 可信度展示 + 用户确认流程（见 §5） | ✅ |
| AI-6 | 看不清或不确定的地方必须明确标出，不得编造 | ✅ |
| AI-7 | 重新分析的触发原因：换模型、Prompt 更新、补充信息、用户主动要求 | ✅ |

### 4.7 AI 对话

| 编号 | 需求 | MVP |
|---|---|---|
| CH-1 | 题目级对话：上下文 = 题目字段 + 当前生效的分析版本 + 可选的原图 | ✅ |
| CH-2 | 流式输出；可以切换模型；每条消息都记录使用的模型 | ✅ |
| CH-3 | 一道题可以有多个会话 | ✅ |
| CH-4 | 全局、空间级、归档级对话，以及「选中若干文件/题目」对话 | ❌（数据模型已支持） |

### 4.8 KnowledgePoint（知识点）

| 编号 | 需求 | MVP |
|---|---|---|
| K-1 | 知识点是空间内的扁平标签，可以选一个 Subject | ✅ |
| K-2 | AI 分析时优先复用空间内已有的知识点名称；每题最多 5 个 | ✅ |
| K-3 | 用户确认分析时，已有的知识点默认勾选；AI 提议的新知识点需要用户勾选才会创建 | ✅ |
| K-4 | 可以手动为题目添加或移除知识点，也可以手动创建知识点 | ✅ |
| K-5 | 知识点管理页（重命名、合并、删除） | ❌（MVP 只提供重命名和删除） |

## 5. AI 结果的确认流程【评审 R3】

### 5.1 状态

每个分析版本有两个独立的状态：

- **执行状态 `status`**：`PENDING → RUNNING → SUCCEEDED | FAILED`
- **审阅状态 `review_status`**（只对 SUCCEEDED 版本有效）：

| 审阅状态 | 含义 | 如何进入 |
|---|---|---|
| `UNREVIEWED` | AI 草稿，尚未审阅 | 分析成功后的默认状态 |
| `CONFIRMED` | 用户认可 | 用户点「确认」；或者用户修正后生成的新版本 |
| `CORRECTED` | 已被用户修正，被新版本取代 | 用户在此版本基础上修正并保存后 |
| `REJECTED` | 用户认为结果不可用 | 用户点「驳回」（可以填写原因） |

### 5.2 规则

1. 一道题同一时间最多只有一个「当前确认版本」（`question.confirmed_analysis_id`）。新确认的版本会替换它，旧版本保留在历史中。
2. **未确认的版本**在界面上始终标为「AI 草稿」，不参与知识点统计，将来也不进入复习和学习画像。
3. **低可信度版本**（见 06 §7）在详情页顶部显示醒目提示。「看不清的部分」要逐条展示，用户查看后才能确认。
4. **确认时**：
   - 用户可以选择把识别结果「采用到题目」（写入 `question.stem_text` 等字段，写入前可以编辑）；
   - 勾选知识点：已有的默认选中，新提议的默认不选；
   - 这些操作在一个事务中完成。
5. **修正**：用户编辑识别结果或分析内容后保存，系统生成新版本（`origin = USER_EDIT`、`parent_id` 指向原版本，直接为 `CONFIRMED`），原版本改为 `CORRECTED`。
6. **驳回后**：可以补充信息或换模型重新分析，生成新版本。驳回的版本保留在历史中。
7. 用户修正过的识别文本可以作为下次重新分析的输入，AI 以此为准，不再依赖自己对图片的识别。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | API Key 只放在后端环境变量中；前端不接触任何 Key；服务默认只监听 127.0.0.1（因为没有登录） |
| 可追溯 | 每个 AI 结果都能追溯到题目、来源文件和页码、Provider、模型、Prompt 版本和输入快照 |
| 数据安全 | 原件不可修改；删除只做软删除；提供备份说明（MySQL 转储 + 存储目录） |
| 性能 | 单用户；上传 20MB 图片不超过数秒；列表接口不超过 300ms；AI 分析异步完成，允许 30–120 秒 |
| 可扩展 | 新增空间、Subject、AI Provider、存储后端都不需要改核心代码 |
| 可测试 | AI 调用可以用 Mock 替换；自动化测试不依赖真实 API |
| 成本可见 | 记录每次 AI 调用的 token 用量 |

## 7. MVP 范围

### 包含

1. 学习空间的创建和选择（含轻量 Subject）
2. 归档的创建和浏览
3. 图片和 PDF 上传（PDF 范围见 07 §4）
4. 题目创建（多来源 + 角色标注）
5. AI 识图 + 分析（多模型可选）
6. 结构化结果、版本、可信度、确认流程
7. 题目列表和题目详情
8. 题目级 AI 对话（流式）

### 不包含（MVP 之后）

登录、多用户；AI 自动拆题；区域框选；复习系统（只预留字段）；学习画像；全局、空间级、归档级对话；RAG、向量库；Redis；Agent 框架；移动端 App；高级统计分析；导出。
